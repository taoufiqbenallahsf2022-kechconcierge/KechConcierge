# SEO investigation — 15 November 2026

Scope: live production HTTP responses and repository source, focused on luxury villas and private transportation for the UK, France, Spain, Italy, Germany and Portugal. No website SEO changes were implemented during this investigation. Separately, the Visitor Page visits tab display was restored as requested; Interactions keep their readable descriptions.

## What was actually checked

Fetched production homepage, robots.txt, sitemap.xml, English/French villa categories, Contact, Packs, Spa, six product pages (two villas, two beach clubs, two vehicles), a nonexistent category, a nonexistent product, HTTP and www variants. Parsed initial response HTML with scripts/styles removed to distinguish visible HTML content from metadata and serialized script data. These are HTTP checks, not a rendered Googlebot session, Search Console inspection, Lighthouse or a backlink audit.

- Main HTTPS homepage and sampled existing URLs: HTTP 200.
- robots.txt: allows public crawling; declares the production sitemap.
- Sitemap: HTTP 200; 540 URL entries. A sitemap is discovery support, not evidence of indexing.
- Sampled public pages: index/follow; self-referencing canonical found on homepage and English/French villa category samples.
- HTTP homepage redirects to HTTPS.
- Random nonexistent category: HTTP 404.
- Random nonexistent product: HTTP 200, noindex/nofollow.
- www probe failed certificate validation with a self-signed-certificate error from this environment. Verify the www certificate/redirect independently before treating this as an origin certificate finding.

## Priorities and evidence

### 1. High: product navigation is implemented with buttons, not real links

`apps/website/src/components/ItemCard.tsx` and `CategoryItemCard.tsx` use a button and router.push for the product destination. This remains a button after rendering. Google recommends anchor elements with href for reliable URL discovery. The sitemap helps discover URLs, but does not replace a usable internal link structure.

Recommendation: render product cards using Next Link / actual anchor hrefs, preserving their current appearance, interaction tracking, mobile gestures and navigation experience. Check homepage collections and category grids in all languages. Do not redesign cards.

Google: https://developers.google.com/search/docs/crawling-indexing/links-crawlable

### 2. High: initial HTML lacks the main commercial content

Homepage response: no h1 and no product collection cards in visible HTML. The English/French villa category responses contain the category heading/intro but no villa results in visible HTML.

All six sampled product pages contain metadata/structured-data output, but their visible HTML body contains navigation/footer and lacks the product h1, description, prices, images and service options. Examples:

- https://moorishconcierge.com/villas/luxury-villa-marrakech-indoorpool-safir
- https://moorishconcierge.com/villas/Villa-luxurious-terracotta
- https://moorishconcierge.com/transportation/transportation-skoda-superB
- https://moorishconcierge.com/transportation/transportation-skoda-Kodiaq

Source confirms client-side loading via effects/stores in Hero, category listings and product page. Metadata being server generated does not make the visible product content server rendered. Google can execute JavaScript, so this observation does NOT prove that these pages are unindexed. It does create a rendering/API dependency for content discovery and warrants URL Inspection's rendered HTML check.

Recommendation: fetch initial public product/category/homepage data on the server and render the same visible content in the initial HTML; keep interactive galleries, booking, filtering, tracking, translations and current design. Avoid hidden SEO-only duplicate text.

Google: https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics

### 3. Medium: important category titles are generic

Live villa category title: "Villas | Moorish Concierge"; h1: "Villas". Vehicle product titles are brand/model names, e.g. "Skoda Kodiaq | Moorish Concierge". These are descriptive names, but offer limited context for searches about villa rental and private transfers in Marrakech. Category metadata pulls managed content, so hardcoding generic replacements without reviewing that content is inappropriate.

Recommendation: review managed category titles, descriptions, introductions and product copy for actual search intent and city/service context. Develop native-language wording for en/fr/es/it/de/pt. Keep product names intact; avoid keyword stuffing or unverified luxury claims. Confirm intent (airport transfer, private driver, chauffeured vehicle, villa rental) from actual offerings and Search Console queries before adding landing pages.

### 4. Medium: unfinished public copy and inconsistent business details

Initial homepage body includes: "This first version is frontend-only. Later, messages and bookings will be connected to your API and admin system." Source: English contactCTA description in messages/en.json.

Contact displays contact@kechconcierge.local; footer uses contact@moorishconcierge.com. Source: contact/page.tsx.

Root LocalBusiness schema uses +212613859834, while the visible footer uses +212763066907. Confirm the intended Moroccan phone before changing it.

Recommendation: remove development copy, use the correct business contact consistently, review all six language dictionaries and structured data. These are content/consistency issues, not proof of a Google penalty.

### 5. Lower: nonexistent product URLs return 200

https://moorishconcierge.com/villas/nonexistent-seo-audit-product returns HTTP 200 with noindex/nofollow. noindex prevents intended indexing, but the response still does not correctly signal a missing product.

Recommendation: distinguish an actual product 404 from a temporary upstream failure; use server notFound for missing products, and do not turn temporary API errors into permanent missing-page or noindex responses. ProductSeoLayout currently returns noindex for any null product, including fetch errors.

### 6. Review sitemap coverage and canonical consistency

Sitemap contains six-language URLs, including Packs and Spa although those were removed from the Services frontend. Their presence is not automatically wrong; removal from navigation did not necessarily mean depublication. Determine which categories should remain publicly indexable. Check sitemap language-home trailing slash redirects and canonical alignment. Do not change product slugs solely because of capitalization or spaces without redirect planning.

## What remains unknown

No access to the property's Search Console data, rendered URL Inspection output or reliable competitor/backlink metrics was available. We cannot honestly assign one cause to low rankings, claim a penalty, assert that all pages are unindexed, or promise positions from the technical issues above.

To finish the ranking diagnosis, collect Search Console Performance for the last three months (Queries, Pages, Countries, Devices, clicks, impressions, average position), Page indexing reasons, and URL Inspection for one villa, one transportation product and their category pages. Inspect Google's selected canonical, last crawl and rendered HTML. Compare intended languages/countries and branded versus non-branded queries. Export data or provide screenshots; do not share account passwords.

## Suggested implementation order

1. Replace button-only product navigation with real links, preserving design.
2. Render initial public content on the server without changing UX.
3. Correct unfinished business copy and inconsistent verified contact details.
4. Improve managed localized category metadata/content for validated service searches.
5. Correct missing-product status handling; review public sitemap coverage.
6. Re-inspect representative URLs in Search Console and measure changes over time.

Performance testing and search demand/competition analysis remain separate checks. This audit did not measure Core Web Vitals or conclude that backlinks are missing.
